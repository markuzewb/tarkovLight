# HANDOFF — инструкция для нового чата / нового разработчика

> **Что это.** Самодостаточный бриф, чтобы продолжить работу над проектом без

## 0. Если вы — новая сессия ассистента

## 1. Продукт и критерий приёмки

Пользователь (русскоязычный) сформулировал так: «в Таркове ничего не видно,
приходится выкручивать гамму; нужна программа, которая подкручивает гамму сама и
улучшает картинку, чтобы всё было видно».

* **Acceptance-критерий:** «всё видно» — тени вытянуты, но без серого молока, без
  клампинга пересветов, без мыла на светлых сценах (Labs/день).
* Не является целью: любые «читерские» механики (подсветка врагов, X-ray, оверлей,
  чтение памяти). Проект позиционируется как настройка вывода изображения.
* FPS-цена должна быть нулевой или около: никаких постоверлеев, только LUT монитора.

## 2. Жёсткие требования пользователя (не отменять без него)

| Требование | Следствие для кода |
|---|---|
| Windows **11** (не 10) | учитывать Auto HDR / HDR-режим / «Ночной свет»: они ломают или перекрывают gamma-таблицу → есть `probe_gamma_support()` и `--check` |
| Режим игры — **Borderless** | не нужны трюки для exclusive fullscreen; но нужен детект чёрного кадра (GDI не видит Exclusive Fullscreen) → реализовано |
| Нужны **оба** артефакта: программа **и** готовый ReShade-пресет | `reshade/Shaders/TarkovBright.fx` + 2 пресета, математика 1:1 с приложением (`tests/test_reshade_sync.py`) |
| «Как бы чего не было с EAC» | никаких инъекций/оверлеев; в README — раздел «Безопасность (честно)» с полным списком вызовов Win32 и оговоркой, что гарантии даёт только BSG |
| Низкий порог запуска | приложение **обязано работать без pip и без сторонних пакетов**; `install.bat` только пытается поставить ускорения |

## 3. Что уже сделано (состояние)

* Ядро: `app/correction.py` — статистика кадра → авто-параметры → 3 LUT → упаковка
  под `SetDeviceGammaRamp`. Numpy = ускорение, не требование (pure-путь даёт те
  же решения: LUT сходятся в пределах 1 уровня).
* Захват: `app/capture.py` — GDI через ctypes (`CreateDIBSection` + `StretchBlt`
  с HALFTONE, даунскейл до ~560 px) → `mss` → `Pillow` → `none`. Единый объект
  `Frame(pixels, width, height, stride, bpp, order)`.
* Авто-контур: `app/engine.py` — `DEFAULT_CONFIG` + 5 профилей, гладкость, мёртвая
  зона, анти-тилт, filmic-knee, пороги.
* UI: `app/main.py` — tkinter-окно с ползунками, хоткеи F7/F8/F9/F10, CLI
  `--headless --always --minimized --profile --gamma --preview --check --restore
  --selftest`.
* Обходные пути, когда LUT недоступна: `Emergency-Gamma.ps1` (чистый PowerShell,
  та же математика, ручной режим) и ReShade-шейдер (осторожно, см. §7).
* Тесты: 4 набора, ~200 проверок, все зелёные; отдельный набор
  `tests/test_nodeps.py` запускает приложение в подпроцессе, где `numpy`/`mss`/
  `Pillow` **заблокированы**.
* `.bat`-обвязка: `_pyfind.bat` ищет **запускаемый** Python (не `where py`!),
  сообщения ASCII, CRLF.
* Git: папка переименована в `tarkovLight` (совпадает с именем репо), `.gitignore`
  (исключает `samples/*.png` ~21 МБ, `dist/`, `config.json`, `.spec`, кэш),
  `.github/workflows/ci.yml` (ubuntu+windows × 3.10/3.12), README с бейджем и
  картинкой `samples/before_after.jpg` (~160 КБ, `make_comparison.py` сам её сжимает),
  `HANDOFF.md`. История: `git init -b main` + 3 коммита + тег `v1.0`,
  `origin` = https://github.com/markuzewb/tarkovLight.git.

## 5. Инварианты, которые нельзя ломать (нарушение = молчаливая поломка)

1. **Раскладка gamma-таблицы = планарно**: `WORD Ramp[3][256]` — сначала 256
   значений R, потом G, потом B, little-endian, 1536 байт, масштаб **`level*257`**
   (не `<<8`!), максимум 65535. На identity обе раскладки побайтово совпадают,
   поэтому тест «γ=1 → identity» её **не ловит** — ловит только проверка на
   тилагованной таблице (`--check` делает это специально).
2. **Каждый канал монотонен non-decreasing.** Немонотонную таблицу драйвер отклоняет
   с `ERROR_INVALID_PARAMETER`; мы проверяем это локально
   (`correction._ramp_words`) до вызова API, иначе юзер видит мутное «вернул отказ».
   Поэтому насыщение/контраст применяются в float **до** округления до 256 уровней.
3. **Цепочка градации** (и в приложении, и в `fx_grade` теста, и в .fx):
   sRGB → linear → black point `(lin-bp)/(1-bp)` → back to sRGB → `+lift*(1-x)²`
   (lift **в encoded-домене**, не в линейном!) → `^(1/(gamma*tint^1.30))` →
   contrast/brightness → filmic knee `x(1+k)/(1+kx)` → saturation (в линейном
   свете вокруг luminance) → clamp_floor → 0..255.
4. Тилт: серо-мир по полосе **p55…p92**, обрезка 1/max_gain..max_gain,
   **ренормализация по геометрическому среднему** (иначе ползёт общая яркость),
   гейт `median > tint_min_median`.
5. `saturation ≤ 1.24` (выше — бандинг на 8-битном выводе).
6. Пороги «достаточно изменилось» считать от числа сэмплов: pure-путь использует
   ~6000 2×2-боксов, распределённых по строкам **равномерно** (не кумулятивным
   шагом — иначе выпадает низ кадра и уезжает p25).
7. `identity_ramp()` и `ramp_bytes(build_luts())` при γ=1 обязаны совпадать
   побайтово; `--restore`/`force_identity` обязаны работать, даже если оригинал не
   прочитался.
8. **Никаких обязательных зависимостей.** `import numpy` только внутри функций,
   где он ускоряет (и в `tools/preview.py`). Проверка — `tests/test_nodeps.py`.
9. Рабочий цикл (`App._tick`) не должен умирать от исключения: обёрнут в
   try/except, причина — в статус окна, лимит 300 подряд ошибок.

## 6. Ловушки, на которых уже обжигались

* `where py` ничего не гарантирует: лаунчер может указывать на удалённый
  `D:\python.exe`. Единственная проверка — запустить и получить версию ≥ 3.9.
* Кириллица в `.bat` на CP866 → каша. `.bat`: ASCII + CRLF. `.ps1`: UTF-8 **с BOM**
  (иначе Windows PowerShell 5.1 читает как ANSI).
* `New-Object 'ushort[]' N` в PowerShell **не работает** (алиас типа в составном
  имени не резолвится) → `New-Object 'System.UInt16[]' N`.
* `ctypes.windll...GetLastError()` нужно читать сразу после отказа; в `ctypes`
  удобнее `WinDLL(..., use_last_error=True)`.
* `GetDeviceCaps(BITSPIXEL)` — бит **на пиксель**, а не на канал: 32/PLANES=1 это
  не «10 бит». 10 бит видно только при PLANES=3; HDR проверяют через
  `GetDeviceCaps(MXDC_ENABLE_HDR=110)`.
* GDI/mss возвращают **чёрный кадр** в Exclusive Fullscreen — нельзя в этот момент
  выкручивать гамму в максимум (реализован детект + предупреждение).
* При HDR/Auto HDR `SetDeviceGammaRamp` может возвращать TRUE и ничего не менять —
  отсюда эмпирическая проба с readback.
* В **RDP/терминальной сессии** гамма-таблицы нет как функции; отказ приходит без
  кода ошибки. См. §7bis.
* Тесты подменяют `capture.Grabber` глобально — чтобы проверить реальный путь,
  делайте `importlib.reload(capture)`.
* Никогда не `rm samples/*_bright.png` — под этот глоб попадает `labs_bright.png`
  (имя сцены!). Тяжёлые png лучше не коммитить, а генерировать (`tools/`).
* Правки «по anchor-строке» в скриптах-патчерах: `read_text()` нормализует CRLF →
  не ищите `\r\n` в тексте; и не оставляйте «no-op guard»-замены — одна такая
  съела объявление P/Invoke в `Emergency-Gamma.ps1` и сломала `Add-Type`.
* Грид-поиск параметров авто-блока требует **мягкой** целевой функции, иначе
  оптимум уезжает в жёсткий край.
* `SetDeviceGammaRamp` каждые 80 мс на части драйверов даёт фликинг → порог
  `min_lut_delta` + «дёргать только если таблицы изменились»; повторный
  «restore» при незанятой таблице — no-op.

## 7. Безопасность / бан (как об этом писать пользователю)

* Программа **не инжектится**: только `SetDeviceGammaRamp`/`GetDeviceGammaRamp`,
  `GetDC`+`StretchBlt` (захват), `GetAsyncKeyState` (хоткеи), и — опционально —
  `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`+`QueryFullProcessImageNameW` /
  `tasklist` для «только когда игра запущена» (снимается `--always`). Нет чтение
  памяти, хуков, оверлея, правки файлов/конфигов игры.
* Гарантий «не забанит» не даёт никто; формулировка в README — «настройка вывода,
  как яркость монитора; решение за BSG/EAC».
* **ReShade в Escape from Tarkov блокируется самой игрой** (BSG, 15.12.2019:
  «Reshade is now officially blocked… no bans, the plugin is just being blocked
  from loading»; свежие отчёты — игра не стартует с файлами ReShade). Пресеты в
  репо — для офлайна/других игр/как справочник формул, **не для онлайна Таркова**.
  Обход блокировки = реальный риск бана, не советовать.

## 7bis. Окружение пользователя (важно для диагностики!)

* Windows 11, доступ к машине **через RDP**. В терминальной сессии
  `SetDeviceGammaRamp` возвращает FALSE **без кода ошибки** — это уже
  диагностировано (`--check` печатает «сеанс: УДАЛЁННЫЙ (RDP)»).
* Следствие: проверять «а работает ли гамма» надо либо на клиенте (там LUT
  применяется к тому, что он видит: `python app\main.py --always`, mstsc на весь
  экран), либо на хосте вне RDP (`tscon 1 /dest:console`, Moonlight/Parsec).
* `python` на хосте рабочий, лаунчер `py` был битый (удалённый `D:\python.exe`).

## 8. Проверки (обязательный минимум перед «готово»)

```bash
python -m pyflakes app/*.py tools/*.py tests/*.py          # должен быть чистым
python -W error::SyntaxWarning -m py_compile app/*.py tools/*.py tests/*.py
python tools/make_samples.py                                # сцены для превью-теста
for t in test_engine test_app test_nodeps test_reshade_sync test_gui; do
    python tests/$t.py || echo "FAIL $t"; done              # все exit 0; test_gui умеет SKIP без DISPLAY
python app/main.py --selftest                               # работает и без numpy
python tools/preview.py --all                               # регрессия чисел (см. ниже эталон)
```

## 9. Очередь задач

1. **LICENSE** в репозитории не выбран (осознанно) — спросить пользователя
   (MIT для «чтобы просто работало», или «no warranty + non-commercial»).
2. **Пуш в `markuzewb/tarkovLight`** — всё готово, ждёт токен (см. §11).
3. Имя: папка/репо `tarkovLight`, внутри всё называется `TarkovBright`
   (окно, exe, `%APPDATA%\TarkovBright\config.json`). Переименовывать или нет —
   решить с пользователем; если да — менять `--name` в `Build-exe.bat`, заголовок
   окна, путь конфига и `reshade/Shaders/TarkovBright.fx` + `TB_`-префикс
   одновременно, иначе рассинхронится `test_reshade_sync.py`.
4. Проверить на реальной Windows-машине (вне RDP): `--check` → OK; горячие клавиши;
   GDI-захват в Borderless; вид окна (tkinter).
5. Опция: авто-режим яркости панели (WMI) как второй контур, если LUT недоступна.
6. Опция: собрать `dist\TarkovBright.exe` и приложить к release (GitHub Release,
   не в git: 21 МБ бинарников в истории не нужны).
7. Опция: пресеты под конкретные карты из скриншотов пользователя
   (`tools/preview.py --profile ... <png>`).
8. Мелочи: `--check` имеет смысл расширить текстом «что делает ReShade-вариант»
   (он блокируется игрой) — уже есть в README; не дублировать.

## 10. Чего НЕ делать

* Не вводить обязательные зависимости (numpy/mss/Pillow/pywin32/keyboard) —
  тогда `pip` снова станет точкой отказа на машине пользователя.
* Не «чинить» HDR-монитор попытками включить аппаратную гамму через DDC/CI или
  драйверные API без явного согласия пользователя.
* Не добавлять оверлей, подсветку контуров, чтение памяти, «видимость врагов» —
  это уже чит, и это ломает договорённости проекта.
* Не переписывать `.fx` на сторонние пакеты шейдеров (`Macros.fxh` и т.п.):
  в `slim`-ветке reshade-shaders нет Levels/Curves/Vibrance, шейдер самодостаточен
  и опирается только на `ReShade.fxh` (`PostProcessVS`, `ReShade::BackBuffer`).
* Не коммитить `samples/*.png`, `build/`, `dist/`, `__pycache__/` (см. `.gitignore`);
  `samples/before_after.jpg` — можно (он сжат до ~160 КБ и нужен как картинка в README).
* Не обещать «100% не забанит» и не предлагать обход блокировки ReShade.

## 11. Github: что осталось сделать

`github.com/markuzewb/tarkovLight` **существует и пустой** («This repository is empty»
— проверено). Local-история готова, `origin` прописан — **не хватает самого пуша**, и
он не может быть выполнен здесь: в песочнице нет `gh`, нет `~/.git-credentials`, нет
`GH_TOKEN`/`GITHUB_TOKEN` (проверено), сеть только исходящая read-only.

Полная инструкция для трёх сценариев (твоя Windows-машина / чат с сетью и токеном /
web-upload без git): **`/home/user/PUSH-to-GitHub.md`**. Артефакты: `tarkovLight.zip`
(1,5 МБ, включает `.git`) и `tarkovLight.bundle` (1,25 МБ, вся история; проверено —
из него клонируется, и тесты из клона зелёные).

Коротко с Windows: распаковать zip → `cd tarkovLight` → `git push -u origin main
--follow-tags`, вместо пароля PAT со скоупом `repo`.

Если `.git` по какой-то причине потерян:

```bash
git init -b main && git add -A && git commit -m "перенос проекта"
git remote add origin https://github.com/markuzewb/tarkovLight.git
git push -u origin main            # нужна учётка: PAT (scope repo) или gh auth login
```
